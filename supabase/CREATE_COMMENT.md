# コメントスパム対策

## 適用順序

1. `inspect_comments_policies.sql` をSupabase SQL Editorで実行し、実際のINSERT / ALL policy名・権限を確認する。このSQLは読み取り専用。`delete_sql` に正確な削除SQL、ALLの場合は `preserve_select_sql` に表示権限を残すSQLが出る。
2. `migrations/202610290002_secure_comments.sql` を実行する。トランザクション内で公開書き込み権限（カラム単位も含む）を剥奪し、INSERT policyを削除、ALL policyを同じ名前・ロール・条件のSELECT専用policyへ置き換える。コメント読み取りの条件は維持する。非公開の制限テーブルとservice_role専用RPCも作成する。生成SQLを別途実行する必要はない。
3. サーバーに `SUPABASE_SERVICE_ROLE_KEY` と `NEXT_PUBLIC_SUPABASE_URL` が設定済みであることを確認する。service role keyをブラウザ用環境変数にしない。
4. Vercelでは入口で上書きされる `x-vercel-forwarded-for` を使用。それ以外ではプロキシが必ず上書きするIPヘッダー名を `COMMENT_TRUSTED_IP_HEADER` に設定する。未設定なら既存の `PV_TRUSTED_IP_HEADER` を使用。任意のクライアントが指定したヘッダーをそのまま転送しない。本番で信頼できるIPを取得できない場合は503で投稿を拒否する。開発環境のみ127.0.0.1へフォールバックする。
5. 任意でサーバー専用の `COMMENT_IP_HASH_SECRET` を設定する。未設定時はservice role keyをHMACの鍵に使用する。鍵の変更は直前30秒のIP照合に影響する。
6. APIと画面を同時にリリースする。SQL適用から切替まで旧画面の直接投稿は拒否されるため、短い切替時間を確保し、開いたままの旧画面は再読み込みする。本作業ではDB実行・デプロイは行っていない。

PV用SQLと独立して適用可能。今回、PVの既存実装は変更しない。

## 制限と検証

- 同一viewer_id **または** 同一IPハッシュについて、セルをまたいで **30秒に1回** まで。どちらか一方を変えても制限する。同じ回線を共有する人にもIP制限が適用される。
- 投稿者/IPごとの順序付きトランザクションロックで複数APIインスタンス・同時投稿を直列化する。セル行もロックして100件上限とcomments_enabledを判定し、保存まで同一トランザクションで処理する。
- セルが存在しない場合404、コメントOFFは403、100件到達は409、連投は429（Retry-After: 30）。保存失敗・IP取得不可は503。APIはDBの内部エラーを公開しない。
- 名前10文字、本文150文字。画面のmaxLengthと同じJavaScript文字列長でAPI検証する（絵文字は2以上を消費する場合がある）。型・NUL文字・空白のみの本文も拒否する。名前の空欄は従来どおり「名無し」。名前・本文はtrimして保存する。DB側でも入力を検証する。
- 生IPは保存しない。HMACハッシュとviewer_idは非公開スキーマに保存する。古い制限記録は同じ識別子の次回成功時に削除する。長期運用で残る記録は定期削除可能：`DELETE FROM private.comment_post_limits WHERE created_at < now() - interval '1 day';`
- コメント表示のSELECT・並び順・最大100件表示は維持する。投稿中は二重送信を抑止し、失敗時は入力を保持して日本語メッセージを表示する。

## 確認

ローカルAPIテスト：`node --test tests/create-comment.test.cjs`

実DBに接続できていないため、policy名の実値確認とDB適用後の動作検証は未実施。適用先のテスト環境で次を確認する。

1. anon/認証済みユーザーのcomments直接INSERTとRPC呼び出しが拒否され、従来のSELECTは可能。
2. 正常投稿・空欄の名前、10/150文字の境界値、超過・型不正・空白本文を確認する。
3. viewer_idのみ同一、IPのみ同一、両方異なる投稿を、同一/別セルへ同時送信する。前二者は30秒内の成功が1件、両方異なる場合は投稿可能。30秒後に再投稿可能。
4. 99件のセルに異なるviewer_id/IPから同時投稿して成功が1件のみとなり、100件を超えないこと。
5. 存在しないセル・コメントOFFへの投稿が拒否されること。コメントOFF更新・セル削除と同時投稿時に行ロック順序に従って整合性が保たれること。
6. コメント表示・セル詳細・PVランキングを確認する。
